## 来源与范围

灵感来自《Handbook of Logics for Knowledge and Belief》2014 年草稿，第 8 章 §8.2.4，印刷页 354–355（上传 PDF 的第 364–365 页），尤其是公式 (8.3)：

`AG(train1_in_tunnel → K1 ¬train2_in_tunnel)`

这里自行明确了状态、许可和动作规则，并没有声称逐行复现书中的实现。项目包含具体模型及一个集合级 CTLK 检查器核心；这不是整个认知逻辑系统的可靠性或完全性证明，也不是第 8 章的完整形式化。

## 模型

两列车 A、B 的位置分别为 Outside、Waiting 或 Inside。每列车另有布尔许可 `permit`。

| 动作 | 条件 | 效果 |
|---|---|---|
| request | 列车在外面 | 改为等待 |
| grant | 列车等待，且没有未释放的许可 | 发放许可 |
| enter | 列车等待且持有许可 | 进入隧道 |
| leave | 列车在隧道中 | 离开并释放许可 |
| idle | 无附加条件 | 状态不变 |

动作按交错方式执行；离开与释放许可是同一步。初始时两车在外面，均无许可。

## 已证明的性质

- `reachable_invariant`：对于每个可达状态，至多一列车持有许可，且进入隧道的列车持有许可。
- `mutual_exclusion`：两列车不会同时在隧道中。
- `knowledge_is_factive`：在可达状态中，知道的命题成立。
- `inside_knows_other_out`：设 i、j 是不同列车。如果 i 在隧道中，那么 i 知道 j 不在隧道中。
- `safe_system_rejects_double_permission`：反例中的双许可状态不能在正常协议中到达。
- `faulty_protocol_counterexample`：错误协议能够到达碰撞状态。
- `faulty_knowledge_counterexample`：错误协议中的碰撞状态也使对应的知识性质失败。

知识定义：i 仅观察自己的位置；对于每个与当前观察一致的协议可达状态，命题 P 都成立时，记作 i 知道 P。这里没有时钟、观察历史或完美记忆。知识结论依赖模型中的协议约束，不表示物理列车无需通信便能知道外部事实。

`inside_knows_other_out` 是书中 (8.3) 的可达状态表述。新增文件进一步将其接入检查器，并直接证明无限执行路径上的对应性质；尚未证明整个检查器的固定点语义与书中完整路径语义等价。书中 (8.4) 的公式与附近文字存在表述差异，本项目不据此声明该性质已验证。

## 错误协议为何会碰撞

错误规则只检查“当前没人进入”，却忽略已经发出的许可。因此可以先后给两列等待的列车授权，再让两车进入。

Isabelle 中的显式路径：

`A 请求 → B 请求 → A 获许可 → B 错获许可 → A 进入 → B 进入`

Python 的广度优先搜索找到同样长度的另一条路径：

`A 请求 → A 获许可 → B 请求 → B 错获许可 → A 进入 → B 进入`

关键差异是“隧道目前空闲”不等于“没有尚未兑现的进入许可”。
