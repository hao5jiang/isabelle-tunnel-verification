## 一键复查

在项目根目录执行：

```powershell
& .\isabelle_tunnel\verify_generated_codec.ps1
```

脚本使用本机已经安装的 Isabelle、Poly/ML 和 Python，不安装新软件。需要更换安装目录时可以传入 `-IsabelleRoot`、`-Python`、`-PolyML`；`-Smoke` 可缩小主要执行用例集。

复查流程：

1. 检查当前理论会话，必要时重新构建。
2. 把明确命名的会话导出提取到新建的临时目录。
3. 将新提取内容与 `generated/EpochCodec.ML` 逐字节比较。
4. 启动真实导出程序，执行独立用例和交互检查。
5. 对隔离的错误副本执行控制测试。

脚本不会覆盖现有核心。若两份内容不同，它会报错并保留新导出的副本，供检查差异。成功时只清理本次创建的临时导出副本。

单独运行完整执行测试：

```powershell
python .\isabelle_tunnel\check_generated_codec.py
```

## 实际导出了什么

公开核心包含 `epoch_encode`、`epoch_decode`、`epoch_checked_successor`，以及连接目标语言整数与自然数的两个转换函数。

导出使用 Isabelle 标准的 `Code_Target_Nat` 和 `Code_Numeral` 支持。SML 端采用 `IntInf.int`，不是用 32 位或 64 位整数承载全部编号。测试覆盖到 64 字节，即 512 位字段边界。

本轮没有导出整个隧道控制器、日志系统或物理设备模型，也没有运行实际网络、磁盘或控制设备。

## 输入入口和错误区别

| 命令 | 例子 | 回复 |
|---|---|---|
| 编码 `E 字节数 上限 编号` | `E 2 65535 513` | `B 1 2` |
| 解码 `D 字节数 上限 字节…` | `D 2 65535 1 2` | `V 513` |
| 后继 `S 字节数 上限 字节…` | `S 1 255 255` | `N`，没有下一轮 |
| 接口探针 `V` | `V` | `ISABELLE_EPOCH_CODEC_V1` |

返回值严格区分：

- `N`：正式核心返回 `None`，例如编号超范围、非字节项、长度错误或无效上限配置。
- `B …`／`V …`：核心返回成功结果。
- `X`：文本、参数数量或入口运行策略拒绝；尚未作为合法自然数输入交给核心。

入口只接受 ASCII 十进制数字串，允许前导零。负号、加号、`~`、十六进制前缀、小数、尾随字符和其他数字字符均拒绝。这个检查很重要：导出的 `nat_of_integer` 按自然数转换规则会把负整数变成 0，不能先转换后再声称拒绝了负输入。

入口的运行策略是：最大 64 字节宽、每个数字串最多 160 个字符、每行最多 132 个字段、每行最多 16,384 个字符。超长行会被读完丢弃后返回 `X`，不会一直保存其内容；下一行仍可处理。大于预期的字节列表只要没有触及入口策略，仍交由核心返回长度错误。例如 n=64、输入 65 项时返回 `N`。

这些上限属于入口策略，不是 Isabelle 定理对 n 的限制，也没有被证明为完整资源安全保证。入口和读写逻辑经过测试与审查，但未在 Isabelle 中形式化。

每条回复都会刷新输出。交互探针在不关闭输入管道的情况下发送两条请求，分别收到探针回复和 `B 1 2`；关闭输入后进程正常退出。超时、编译错误、异常退出、多余输出、错误输出和响应条数不符都会使测试失败。

## 405,588 条请求的组成

- 一字节：每个上限 0–255 与每个值 0–255，分别执行编码、解码和后继，共 196,608 条。
- 二字节：最大上限下完整覆盖 65,536 个值，分别执行三种操作，共 196,608 条。
- 边界与固定种子用例：11,541 条，包含 0、1、2、4、8、16、64 字节。
- 其余 831 条：超范围、畸形字节列表、无效配置、文本和策略错误、出错后继续处理、空字段和结束输入等。

每条预期结果由 Python 标准库的 `int.to_bytes`／`int.from_bytes` 及单独的接受条件计算，不复用之前 Python 模型的编码实现。运行时明确传递要加载的核心绝对路径，并在测试前后核对核心、入口和 Poly/ML 文件哈希。

本轮完整批处理的进程运行时间约 0.9–1.1 秒；这个数字不是基准测试结论。交互探针另计，未包含在 405,588 条内。检查器自身还用五个故意错误的响应检验了值和输出格式检查。

## 错误副本控制

`check_codegen_negative_controls.py` 只在临时目录创建副本，结束后确认真实导出文件未改变。

1. 将解码用的基数 256 精确改为 255。程序仍能编译，但测试检出本应为 `V 256` 的结果变为 `V 255`。该项不能仅凭编译失败算作通过。
2. 增加 SML 语法错误。测试报告指定副本的编译错误，不回退使用正式核心。
3. 只增加注释。行为检查仍通过，但 SHA256 不同，说明行为用例通过不能替代来源核对。

这些控制说明本轮检查能发现所注入的错误，不证明测试框架能发现每一种错误。
