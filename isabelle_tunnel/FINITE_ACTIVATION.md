## 耗尽规则

设 L 是本次完整执行期间不改变的自然数上限。0 是启动轮次；服务轮次从 1 开始。

| 情形 | 协议动作 |
|---|---|
| 当前已提交轮次小于 L | 可以准备下一轮，正常执行日志、清场与提交协议 |
| 当前轮次等于 L，再请求切换 | 只设置停发标志，不准备 L+1，不更改 owner、日志、占用或消息历史 |
| 当前轮次等于 L，收到提交动作 | 保持状态，不通过旧事务重新开放发送 |
| 四类携带编号的网络事件中，编号大于 L | 忽略该事件，不进入协议处理 |
| 设备提交、门槛启用、掉电恢复、旧命令投递、物理退出 | 继续按原协议规则处理 |

四类编号事件是进入命令投递、隔离请求投递、清场确认发送和清场确认接收。其他事件没有以占位字段参与编号过滤。

没有增加额外的持久化“耗尽锁”。停发保持由已提交轮次不再向后续轮次推进，以及耗尽时不能重新提交开启发送共同建立。L=0 时没有可分配的服务轮次。

## 编号范围覆盖哪里

`journal_payloads` 不只检查当前可恢复记录，还检查两槽中的部分记录、完整记录，以及证明用的提交历史列表。

- 控制器：两槽的轮次载荷、提交历史及当前已提交轮次。
- 每个设备：两槽载荷、提交历史及恢复后的磁盘门槛。
- 当前生效的内存拒绝门槛。
- 已发进入命令、隔离请求、已发确认、已收确认四组消息历史。

这样不会出现“当前轮次没有越界，但非活动槽里已经写入 L+1”的遗漏。

编号有界不表示整个模型的存储空间已经有界：提交历史是证明用列表，长度没有上限。协议仍以自然数建模，没有执行真实的整数溢出操作。

也没有要求每条报文使用不同编号：未提交轮次可以重试，报文可以重放。保护目标是已提交轮次不回绕，以及不再分配超上限轮次。

## 主要正式结论

| 定理 | 内容 |
|---|---|
| `journal_payloads_prepare`、`flush`、`commit`、`crash` | 两槽与提交历史的载荷条件跨日志事件保持；准备新值需要新值满足条件 |
| `finite_activation_step_valid`、`finite_activation_history_valid` | 有限轮次包装协议的每步与执行前缀保持安全及范围不变量 |
| `finite_activation_mutual_exclusion` | 两列车不能同时实际占用隧道 |
| `finite_activation_all_payloads_bounded` | 存储、报文、已提交轮次、磁盘与内存门槛均受同一上限约束 |
| `out_of_range_is_ignored` | 超上限的编号事件不改变状态 |
| `exhausted_step_keeps_epoch_and_stop`、`exhausted_run_keeps_epoch_and_stop` | 达到上限且停发后，每步及后续有限执行保持该轮次和停发状态 |
| `cap_handoff_attempt_stops_emission` | 达到上限后，再请求切换精确对应只设置停发标志 |
| `zero_limit_run_keeps_initial_epoch_and_stop` | 上限为 0 时，从启动状态出发的每段有限执行都保持轮次 0 和停发状态 |
| `exhausted_floors_equal_limit` | 已提交轮次为 L 时，每个设备的磁盘与内存门槛都等于 L |
| `cap_enabled_command_has_last_epoch_and_owner` | 通过进入门槛的已发命令只能属于最后轮次和当前 owner |
| `exhausted_older_entry_rejected` | 此时小于 L 的进入命令不能执行 |
| `stopped_new_entry_is_ignored` | 停发状态不能发出新的进入命令 |
| `last_round_delivery_after_stop` | 满足来源与在线条件时，最后轮次已发的命令在停发后仍可以执行 |
| `final_round_used_then_stopped`、`stopped_final_round_can_still_enter` | L=1 的具体可达见证，展示最后轮次保留使用能力和停发后的在途执行 |

## 停发不是急停，也不是保证清场

达到上限时，由协议不变量得到：

`已提交轮次 L ≤ 内存门槛 ≤ 磁盘门槛 ≤ L`

因此两种门槛都等于 L，低于 L 的旧命令已失效。仍可能执行的是最后合法轮次、当前 owner 对应的已发命令。

可达见证为：

1. 上限为 1，完成 A 的轮次 1 切换，发出进入命令。
2. 请求切换到 B；协议停发，仍保留 A 的许可与已发命令。
3. A 的轮次 1 命令迟到，A 仍能进入；B 不会因此得到许可。

物理退出仍允许。独立测试还检查了退出后再次重放最后轮次命令的情形，仍可再次进入。因此不能从停发推出最终退出、永久清空或急停。

达到 L 后也不能再提交新 owner 或 `None`。最后轮次发生控制器崩溃时，发送会停止，并且没有剩余轮次供重新开放。这是安全与可用性的明确取舍。

## 与前面证明的关系

`Journal_Bounds` 是通用日志载荷保持引理，不改变 `Checkpoint_Journal` 的规则。

`Finite_Activation` 包装 `Endpoint_Activation`，复用其安全不变量及普通步骤的保持定理；新增仅停发分支单独证明安全。该分支不等同于原模型的完整 `BeginHandoff` 或 `ControllerCrash`。
