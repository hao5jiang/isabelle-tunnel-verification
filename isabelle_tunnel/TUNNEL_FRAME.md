## 格式与接受条件

每次解析接收一份完整数据报，不处理分段字节流。

| 字节位置 | 字段 | 合法值／含义 |
|---|---|---|
| 0–1 | 格式标记 | 十进制 84、75，即 TK |
| 2 | 版本 | 1 |
| 3 | 消息类型 | 1：进入命令；2：轮次隔离请求；3：接收清场确认 |
| 4 | 设备标签 | 0：A；1：B |
| 5 | 轮次字段字节数 | 必须等于本地配置 n |
| 6 起 | 轮次数据 | 恰好 n 字节，小端序 |

设 n 是配置的轮次字段字节数，L 是轮次上限。完整报文要求 `0 < n < 256` 且 `L < 256^n`；解析出的轮次 k 满足 `k ≤ L`。n、L 在本轮执行中不变化。整体长度必须是 `6+n`，每个列表元素小于 256。

这里的长度字段只表示轮次载荷宽度，不是可变业务载荷长度，也不是能覆盖整个 256 字节范围的总长字段。

例子：n=2、L=65535，A 的第 513 轮进入命令为：

```text
84 75 1 1 0 2 1 2
```

额外尾随字节、拼接第二份报文、短报文、未知类型、未知设备、错误版本、超范围轮次都会被拒绝。有效类型或有效设备标签之间的修改可以形成另一份合法报文，因此格式检查不是篡改检测。

## 本地动作与确认来源

网络只能解出三类接收事件：`DeliverEntry`、`DeliverFence`、`ReceiveClearAck`。类型 3 仅表示接收已有确认，不能调用生成确认的 `SendClearAck`。

本地动作使用独立的数据类型；设备掉电、恢复、日志提交、门槛启用、真实退出和确认生成不是网络命令。报文配置无效时，网络入口拒绝输入，但本地动作仍按有限轮次规则执行。独立检查新增了四组此类回归，防止把配置错误实现成“整个设备不再行动”。

`forged_ack_not_in_history_is_ignored` 证明：没有出现在模型确认历史中的确认被忽略。但历史来源可信仍是既有假设，不是本轮实现了密码认证；攻击者仿造已有字段等情形仍受原协议规则及假设约束。

## 运行入口与形式范围的区别

形式报文允许 n=1–255；手写文本入口为了限制单次资源开销，只开放 n=1–64。输入 n=0 交由正式核心拒绝，n>64 则由入口拒绝。数学上合法的更宽报文没有在这个文本服务中开放。

文本入口还限制每个数字串最多 160 字符、每行最多 132 个字段、每行最多 16,384 字符。只接受 ASCII 十进制数字串，先拒绝负号等无效文本，再转换为自然数；不会先把负整数变成 0 再检查。

| 文本请求 | 结果 |
|---|---|
| `V` | `ISABELLE_TUNNEL_FRAME_V1` |
| `E 2 65535 1 0 513` | `B 84 75 1 1 0 2 1 2` |
| `D 2 65535 84 75 1 1 0 2 1 2` | `P 1 0 513` |
| 核心拒绝 | `N` |
| 文本或入口策略拒绝 | `X` |

SML 核心使用 `IntInf.int` 支持自然数运算，不是直接用 64 位机器整数保存全部轮次。文本入口、运行器、编译器、操作系统和机器码没有获得本轮 Isabelle 证明。
